# people/

Rider models — the "little agents" of manual §14 who walk to a stop, wait, and board, and the crowd
in §16's station view that mirrors the live waiting count.

**The budget here is not the vehicle budget, and the reason is instance count.** A bus appears a
dozen times on screen; a crowd is hundreds. At the vehicle allowance, 300 waiting riders would cost
1.8 million triangles for background detail, against ~54,000 for the entire fleet on screen. A
person's budget is therefore derived from how many are ever drawn at once, not from how a person
"deserves" to look — see [renderer-3d.md](../../docs/design/renderer-3d.md) §4, "People", for the
full derivation.

## Budget

| | You author (LOD0) | Pipeline generates (LOD1) |
|---|---|---|
| Triangles | **≤ 600** | 200 |
| Optimised bytes | **≤ 12 KB** total for the pair | |

Six hundred triangles is a blocked-out figure: 6- or 8-sided limbs, a head, no fingers, no face, no
separate hair shell, no folds. One mesh per pose — `stand`, `walk`, `sit`, plus a spare (§4's
"3 poses + 1 spare") — each its own `.glb`.

**LOD1 is not generated by the pipeline yet.** `npm run models` will validate a supplied
`<name>_lod1` node if you provide one (same convention as a vehicle's `Mk2_Add`: a named node
alongside the LOD0 mesh, not a separate file), but if you don't, it says so explicitly and ships
LOD0 only — this is an honest gap, not a silent one, until generation lands.

## Material slots

Five named slots, wired for a **per-instance palette**, not livery — a person has no brand colour,
so this is what "variation" means here:

- **Required:** `Skin`, `Top`, `Bottom`
- **Optional** (reported by the validator, never enforced): `Hair`, `Bag`

Leave every slot's base colour at its default. The pipeline merges the five into one shared material
and the renderer overwrites each slot's colour per instance from a palette (6 skin tones, 12 tops,
8 bottoms, 6 hair colours — 3,456 combinations from one mesh); whatever you author into a slot's
base colour is thrown away, not previewed.

## What most often makes a person model unusable

**Any texture at all — rejected outright, not converted.** Every other category (vehicles, depots,
stops, buildings) gets a supplied texture converted to KTX2 with a warning. A person does not:
instancing means one shared material across every rider on screen, and "a face at 10 px is noise."
If your DCC baked anything to a texture — including AO — strip it before export; there is no path
that ships it.

Two more reject rules, not auto-fixed like elsewhere in the pipeline:

- **Vertex colours present and not uniformly white.** `COLOR_0` is reserved for the pipeline's
  per-instance palette slot mask, not for anything you paint.
- **A skin with more than 20 bones.** A rig within that limit is accepted and stripped with a
  warning, not used — v1 ships static poses plus positional movement only, because `InstancedMesh`
  can't skin hundreds of riders affordably. The 20-bone door stays open for a future station-view-
  only animated crowd; it isn't used yet, so don't spend rigging time on it for v1.

## Conventions

Same as everywhere else: `.glb` only, 1 unit = 1 metre (a standing figure is ~1.75 m, seated ~1.3 m),
pivot at floor centre between the feet, no cameras, no lights, no UV0 required.

## Before you drop a file, or after — check it in the viewer

`npm run viewer` opens a standalone page that loads one `.glb` at true scale with a 1 m reference
cube — useful for a scale/pivot/material-slot sanity check before or after running the pipeline.
